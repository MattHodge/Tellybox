# Interface languages: English, Dutch, German (NF-13)

Status: requested by the owner 2026-09-28 ("plan first, then fan out to at most 3 subagents, PR when done"); built the same day.

## Goal

Each browser gets its own language, chosen from its preferences, with no setting to pick. A parent whose browser prefers English gets English; one whose browser prefers Dutch gets Dutch. German is the third language. Anything else falls back to English.

## Scope

- **Admin pages:** all text in the templates, flash messages, validation and other errors raised by our own code, the live text written by the admin JavaScript, and dates, durations and sizes.
- **Kid app:** it has no visible interface text (KA-2), apart from content titles. Only the screen-reader labels ("Home", "Pause", "Time left", …) and `<html lang>` are translated.
- **Not translated:**
  - Content: video, show and playlist titles.
  - Error text that comes from yt-dlp or YouTube.
  - The CLI and the logs.
  - The docs.

## Design

- **Choosing a language:** `tellybox/i18n.py` parses `Accept-Language`, honouring q-values and matching `nl-BE` to `nl`, and picks from `("en", "nl", "de")`, falling back to `en`.
  - A middleware in `create_app` stores the choice in a `contextvar` for the request (`current_locale()`).
  - The middleware also sets `Content-Language` and adds `Vary: Accept-Language`.
  - The kid app is a static page, so its JavaScript picks the language from `navigator.languages` with the same rules.
- **Catalogs:** gettext `.po` files in `tellybox/locale/{nl,de}/LC_MESSAGES/messages.po`, with the English source text as the msgid.
  - [Babel](https://babel.pocoo.org) reads them at startup, so no compiled `.mo` files and no build step. It also formats dates in each language ("maandag 28 september 2026").
  - `babel.cfg` and `scripts/i18n.sh` extract strings into `tellybox/locale/messages.pot` and update the catalogs.
- **Marking text:**
  - In Python: `from tellybox.i18n import _, ngettext`.
  - In Jinja: `jinja2.ext.i18n` with new-style gettext, so `{{ _("Add %(n)s videos", n=count) }}` and `{% trans %}` escape and interpolate safely.
  - Flash messages are translated when they're created, in the request's language.
- **Admin JavaScript:** strings the scripts write at runtime are declared in `tellybox/web/admin/js_strings.py` (marked with `N_()`, so extraction finds them).
  - `base.html` embeds that list, translated, as `<script type="application/json" id="i18n">`.
  - `admin/static/i18n.js` exports `t(msgid, vars)` and `tn(singular, plural, n, vars)` for the other scripts.
  - So one set of `.po` files holds every string.
- **Formatting:** the `minutes`, `duration` and `bytes` filters, and their JavaScript twins, take their units from the catalog ("1 u 05 min", "1 Std. 05 min"; "min" stays in every language). History and the dashboard format dates with `babel.dates`.
- **Tone:** informal. Dutch uses "je"; German uses "du" and capitalises nouns. The wording is short and plain, suitable for a phone screen.

## Tests

- **Language choice:** a table of `Accept-Language` headers, including missing, `*`, q-values, regional variants and unsupported languages.
- **Catalog completeness:** the test extracts every marked string from the Python code and templates and requires a non-empty, non-fuzzy translation in `nl` and `de`. The `%(name)s` placeholders must match the English. This keeps future text from shipping untranslated.
- **Rendering:** every admin page renders under `nl` and `de` with the right `<html lang>`. Spot checks look for known phrases, and the JSON block carries every string the scripts use.
- **Kid app:** its three label dictionaries must have the same keys.
